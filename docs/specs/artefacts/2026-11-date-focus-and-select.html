Date focus ring and select height

Two chrome changes the real-browser accessibility specs found (#19). Each section shows what ships now beside the proposal, in light and dark. The first row in each section is a still picture of the focused state. The second row is live: Tab or click into the controls in Chrome, Firefox and Safari to compare.

1. A focus ring on date and date-time inputs (WCAG 2.4.7)

Today the date popover's input and the Publish sheet's “Publish at” input show no focus ring in Chrome or Safari. Only the browser's own segment highlight remains. Firefox already shows the ring. The proposal gives these inputs the same accent ring every other control has. One difference: it also shows when the input is clicked, not only when it is reached by keyboard, because the browsers give no keyboard-only signal for these inputs.

2. A select as tall as every other control (documented 44px; WCAG 2.5.8)

In Safari the Status select and the Revisions drawer's document picker are 23px tall. The chrome promises 44px controls, and 23px is also under the 24px WCAG 2.5.8 minimum. Safari ignores the height on a native select, so the proposal draws the select without native styling. It then honours the control height in every browser and gets a chevron in the muted colour. This changes the select's look in Chrome and Firefox too, which today show their native arrow. The native menu of options still opens, and Windows high-contrast mode keeps the native control.
