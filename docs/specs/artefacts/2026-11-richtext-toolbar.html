Rich text toolbar (#37)

This is the @yl/editor/richtext widget. The editor types straight into the host element, so the page's own typography stays, as with the text widget. A toolbar floats just above the field, where the badge sits today. It holds the fixed formatting set (bold, italic, link, bulleted and numbered lists, and headings when the field turns them on), then Cancel and Done. It uses the --cms-* tokens, plus one new size token, and adds a handful of classes to chrome.css (the block marked proposed in this file's head). Its position comes in as --cms-toolbar-top and --cms-toolbar-left, the same way as the badge and popover, so it needs no inline styles. Hosts restyle it the way they restyle the rest of the chrome: every rule is in :where(), so any host selector or token override wins.

1. Try it

Click the text, or Tab to it and press Enter. Paste something with formatting from another page to see the paste options; Ctrl/⌘ + Shift + V pastes plain text straight away. The demo uses the browser's execCommand rather than TipTap, so formatting and paste details are approximate. Focus order, keyboard, pressed states, link entry and tooltips, Cancel and paste options behave as proposed. The box under the field shows the HTML that would be stored.

2. States

These are still states. A pressed button uses the accent fill, like the primary button, and announces aria-pressed="true". Every button is 44px tall, the existing --cms-control-h. The toolbar is a single tab stop: arrow keys move between its buttons (roving tabindex).

Keyboard focus on Italic, with tooltip new

The tooltip shows the name and shortcut on hover or keyboard focus, using ⌘ on Apple devices and Ctrl elsewhere. Screen readers get the name from aria-label and the shortcut from aria-keyshortcuts, so the tooltip is aria-hidden. Esc hides it without moving focus (WCAG 1.4.13).

Link entry · new link new

Link or Ctrl/⌘ + K opens a row inside the toolbar, and focus moves to the input. Enter applies it and Esc closes the row. Either way focus goes back to the text with the selection kept. With nothing selected, the address itself is inserted as the link text. A bare example.com gets https:// added.

3. Keyboard

This follows the ARIA toolbar pattern. Nothing traps focus: Tab always moves on, and leaving the field and toolbar commits, like every widget.

Where Key Does
Text Ctrl/⌘ B Ctrl/⌘ I Bold, italic
Text Ctrl/⌘ K Open the link row
Text Ctrl/⌘ ⇧ 8 Ctrl/⌘ ⇧ 7 Bulleted list, numbered list (TipTap defaults)
Text Ctrl/⌘ ⌥ 2 Ctrl/⌘ ⌥ 3 Heading, subheading, only when the field allows them
Text Alt F10, or Tab outside a list Move focus to the toolbar, onto its last-used button
Text, in a list item Tab / ⇧ Tab Nest or un-nest the item. Alt F10 still reaches the toolbar
Text Ctrl/⌘ Enter Done: commit and close
Text Ctrl/⌘ ⇧ V Paste as plain text
Text, paste options up Alt F10 Focus Plain text in the paste options
Text Esc Cancel: put the field back as it was and write nothing. The Cancel button does the same, for touch
Toolbar ← → Home End Move between buttons (wraps at the ends)
Toolbar Enter / Space Press the button. Focus goes back to the text, except for Link, which opens its row
Toolbar Esc Hide the tooltip if one shows, otherwise back to the text. It doesn't cancel
Toolbar ⇧ Tab / Tab Back to the text, or move on past the toolbar (which commits)
Link row Enter / Esc Apply, or close the row. Either way back to the text

Done and Cancel reuse done and cancel. The Aa glyphs and the B and I letters are drawn, not read out. Their names come from the strings above.

5. Decided on the first round

a. Paste. Formatting outside the set is dropped silently. Paste options offer Keep formatting or Plain text after a formatted paste, and Ctrl/⌘ + Shift + V pastes plain.

b. Cancel. Folded into this ticket: a Cancel button next to Done.

c. Heading glyphs. Aa in two sizes, taken from the size tokens a host sets.
