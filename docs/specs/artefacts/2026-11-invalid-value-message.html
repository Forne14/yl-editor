A visible message for an incomplete value

Since the review fixes in #21, a half-typed date or a number the browser can't read never erases the stored value. Pressing Enter keeps the popover open, and leaving it keeps the saved value. Today the reason is only announced to screen readers, so a sighted editor sees nothing happen. WCAG 3.3.1 (Error Identification, level A) asks for the error in text. The proposal shows the same text on screen. It reuses the red line the Publish sheet already shows under “Publish at” for a past time, and the existing info toast, so it adds no CSS.

1. Enter on an incomplete value: a line under the input

The line appears when Enter is refused and goes away as soon as the value becomes readable or empty. The input gets aria-invalid="true" and points at the line with aria-describedby, so a screen reader reads it with the field. Inputs are shown as text so the half-typed values stay visible on this page.

2. Leaving with an incomplete value: an info toast

Clicking elsewhere or opening another field closes the popover and keeps the saved value. The proposal shows the invalidValueKept string as an info toast, which hides itself like every info toast. Nothing is saved, so there is nothing to retry.
