When may a date-ordered list re-sort itself under the editor?

#43 (lists: drag, row/grid, data-order announcement), PR #52. Drag and row/grid lists are done and green; this is only about order="data" lists (events by date). No visual or copy change in any option.

Where it stands

Only the page knows a data-order list's sort, so after a save the chrome fetches the page and swaps the list's markup in (your ruling this morning: in the background, no lock, wait while an interaction is in progress). Each review round finds another interaction the swap lands on:

Round Refresh findings What the swap landed on
1 3 important a field open in another list; fields refused while it ran; focus dropped to the page
2 1 important, 2 nits a drag in progress; a field still opening; a newer request dropped
3 1 important, 2 nits focus on Add pulled back to the saved field; an open chip menu closed; a wrong position announced

Waiting for "an interaction in progress" means listing every kind of interaction (open, opening, drag, chip, a pressed button, a link, a text selection…) and that list never ends. The question is what the swap may touch.

Options

A · Re-sort only what the editor is still on recommended

Right after the save, the refresh runs only if focus is still on the saved field (Enter in a date, the usual case) or on nothing, and no pointer is down. Then the event moves, focus follows the field, and the new place is announced, as the prototype shows. If the editor has moved on to anything else in that document's lists, the refresh waits until focus and pointer have left those lists, then swaps without moving focus and announces the new place.

One rule, checked in one place: the swap never replaces markup holding focus or a pressed pointer, except the saved field itself. No list of interaction kinds to keep up to date.

Editor: the Enter case works as designed. Tab on into the next event's fields and the list re-sorts once you leave it. Site developer: nothing.

B · Re-sort only once the editor leaves the list

Same rule without the exception: nothing re-sorts while focus is inside the lists. Simplest and safest, but the Enter case no longer moves the event in front of the editor, so "focus follows the field" is dropped from #43.

C · No live re-sort: ship #43 without it

A data-order list keeps its order on screen until the next page load; the saved date shows straight away, but the event doesn't move and nothing is announced. The re-sort becomes its own later ticket. Drag and row/grid lists merge now.

D · Keep patching

Round 4: also wait for an open chip menu, keep focus on Add. On the trend so far, more rounds follow.
