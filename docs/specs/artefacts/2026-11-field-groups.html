Field groups

#44 · Chrome: group close plain fields in one outline (no overlapping dashed outlines). Prototype; all rulings made 2026-11-28.

Your rule from 2026-11-11: no overlapping dashed outlines. Lists already follow it (#28): one outline, thin dashed lines between items and fields. Plain fields outside lists still get one outline each, and on the demo page those cross. This page proposes the same treatment for plain fields. G1–G4 are ruled; G5–G10 come from walking through the build and are asked, each with what it looks like. Everything below is live: hover, click and Tab through the fields.

3 · Ruling G1: how a group is declared

A · A wrapper attribute

The host marks the element that holds the fields. Every field inside it (not inside a list) is one group. 

<section data-edit-group>
  <h2 ${attrs(about("title"))}>…</h2>
  <p ${attrs(about("body"))}>…</p>
</section>
// or ${attrs(editable.group())}
  • Predictable: the outline is where the host put it, at every width.
  • New public surface: data-edit-group and a helper on editable().
  • A host that forgets it gets today's crossing outlines, so A comes with the warning below.

B · Found from proximity

The chrome groups any fields whose outlines would touch or cross, and draws one frame around their union.

  • No host work.
  • Groups change with the layout: drag the corner of the box below. Wide, the author and date have an outline each; narrow enough to wrap, they join and a frame appears around them.
  • The union of two far-apart fields can cover markup of the host that isn't editable (an image, a button) and the frame can cross a list's frame.

4 · Ruling G2: does a group carry a tag?

Lists have a tag on their top edge ("Artists · 3 of 6"). A group has no count.

A · No tag; each field keeps its badgeRuled 2026-11-28

Hovering or focusing a field shows its badge, as today. The frame says "these belong together"; the badge says which one you're on. No new text. The badge sits just above its field, so it covers the line above it, as it does in a list item today.

5 · Ruling G3: a locked field inside a group

A group can hold fields of several documents (a heading from pages/home, a footer line from settings/site), so one field can be locked while the others aren't. Today a locked field's outline is muted.

A · Frame stays accent; the locked field is markedRuled 2026-11-28

The frame is muted only when every field in it is locked. A locked field shows a thin muted dashed outline on hover and its muted badge with the reason, as today. Clicking it shows the reason as a toast.

6 · Ruling G4: groups and lists

A · A list is never inside a groupRuled 2026-11-28

Fields inside a data-edit-list belong to the list, never to a group around it. What happens to a group whose wrapper holds a list is G5; a group inside a group is G7. (The first draft said "innermost wins" and "lines stop at the list's frame"; both still drew a dashed outline around another, so they are replaced by G5 and G7.)

B · A group may wrap a list

The list's frame is drawn inside the group's frame. That is a dashed outline inside a dashed outline: the nesting #28 ruled out (D1).

7 · Ruling G5: a group wrapper that holds a list

The host wraps a heading, a list and a closing line in one data-edit-group. By G4 the list's fields stay the list's. What is left of the group?

A · The group is droppedRuled 2026-11-28

Its fields get plain outlines, as if the attribute weren't there, and console.warn names the wrapper. No dashed outline goes around another. 

[yl-editor] data-edit-group on
<section.about> holds a list
(pages/team/list:members).
The group is ignored.

8 · Ruling G6: what the frame goes around

The wrapper can hold markup that isn't editable, like the facts list's labels.

A · The wrapper's boxRuled 2026-11-28

The frame is the wrapper element's box plus the 12px padding, as a list's frame is its host's. Labels, icons or an image inside the wrapper sit inside the frame, and lines run its full width. The host decides the frame by choosing the wrapper.

11 · Ruling G9: the helper (public surface)

Nothing changes on screen; this is what a site developer writes.

A · On the document's helper, like .list()Ruled 2026-11-28

const about = editable(
  editing ? "pages/about" : undefined,
);

<section ${attrs(about.group())}>
  <h2 ${attrs(about("title", "text"))}>…
  <p ${attrs(footer("line", "text"))}>…
</section>
  • Renders data-edit-group only in edit mode, like every other helper, so visitors never get the attribute.
  • It hangs off one document's helper, but the group can hold fields of any document (the footer line above). The docs say so.

B · A static editable.group()

<section ${attrs(editing ? editable.group() : {})}>
  • Not tied to a document.
  • It can't know whether the page is in edit mode, so the host writes the condition or ships the attribute to every visitor.

12 · Ruling G10: what the warning (G1 C) checks

A group frame sits 12px outside its wrapper, so a plain field just below it can have an outline that crosses the frame.

A · Any two dashed outlines that crossRuled 2026-11-28

Field and field, field and group frame, field and list frame, group and list, group and group. Each crossing pair is warned once per mount; it is checked again on resize but never repeated. Fields with no size (hidden) are skipped. The case below warns. 

[yl-editor] The outline of
"settings/site/footer" crosses
the group on <section.about>.
Move it into the group, or
add space between them.

Rulings

G1 Ruled C: a data-edit-group wrapper, plus a console.warn when outlines cross.
G2 Ruled A: no tag; field badges as today. No new chrome text.
G3 Ruled A: a locked field stays in its group; the frame is muted only when every field is locked.
G4 Ruled A: list fields never join a group.
G5 Wrapper holding a list. Ruled A, the group is dropped, fields plain, a warning.
G6 What the frame goes around. Ruled A, the wrapper's box plus 12px. What inside it is editable is the host's choice; the chrome has no opinion and no warning about it.
G7 Group in a group. Ruled A, the outermost wins, a warning names the inner one.
G8 Group in a list item. Ruled A, ignored, a warning.
G9 Helper. Ruled A, editable(doc).group(), attribute only in edit mode.
G10 Warning scope. Ruled A, any two dashed outlines that cross, once per pair per mount.

Settled by this page, so a bug if review finds otherwise: no tint on hover, no Tab stop for a group, a group left with one field drawn as a plain field, the list tokens (--cms-list-pad, --cms-list-line) reused, and cms-group, cms-group__frame, cms-group__sep documented as styling hooks. Not changing: fields outside a group, list frames, the badge, keyboard order (Tab still visits each field in page order; the group adds no stop), and the CSP rule (positions only through custom properties).
